# Terminology

The following terms are used consistently throughout the Harmonia ecosystem.

<br>

### Component

A reusable user interface element that encapsulates appearance, behavior, accessibility, and interaction.

<br>

### Specification

The implementation-independent definition of a component or system.

<br>

### Implementation

A platform-specific realization of a specification.

<br>

### Continuity

The preservation of object identity throughout user interactions.

<br>

### Motion

The system responsible for communicating change between interface states.

<br>

### Design Token

A platform-independent design value such as color, typography, spacing, radius, elevation, or duration.

<br>

### Platform Package

A package that implements Harmonia for a specific platform.

<br>

### Showcase

The public reference implementation used to demonstrate the Harmonia ecosystem.

<br>

### Design Asset

A canonical resource that defines the visual language of Harmonia, including Figma files, icons, illustrations, and design tokens.

<br>

### Automation

Documentation, workflows, templates, and supporting resources that improve the efficiency and consistency of development.

<br>

### Source of Truth

The authoritative location where information is defined and maintained.

<br>

### Monorepo

A repository containing multiple related packages that are developed and versioned together.
